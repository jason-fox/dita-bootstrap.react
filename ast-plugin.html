DITA Bootstrap AST Plug-in & Publishing

Simple guide on publishing DITA documentation into the React Harness data store, comparing transtypes, and automated CI publishing.

Plug-in Overview & Installation

The org.dita-bootstrap.ast plug-in allows authors to publish DITA documentation into the React Harness library. Install the plug-in into your DITA Open Toolkit instance:

# Install plug-ins using the dita command:
dita install fox.jason.extend.css
dita install org.dita-bootstrap.ast

Publishing to the Document Store

Publishing your documentation set requires a single command:

# Publish documentation directly into the data store:
dita --input=path/to/your.ditamap \
     --format=ast-bootstrap \
     --output=react-harness/data-store/data/my-doc-set

Move or save the generated files to the data store directory (data-store/data/my-doc-set)—and that's it! The data store automatically discovers your document set and adds it to your browser library catalog.

Publishing Transtypes:

ast-bootstrap (org.dita-bootstrap.ast)
Generates interactive documentation files for the React Harness web reader and AI Assistant chat.
html5-bootstrap (org.dita-bootstrap.html)
Generates static HTML5 web pages styled with Bootstrap 5.3 for standard web servers.

Customizing Chrome (Headers & Footers)

Custom navigation headers and footers can be passed during publishing via command-line options:

dita --input=path/to/your.ditamap \
     --format=ast-bootstrap \
     --args.hdr=path/to/custom-header.xml \
     --args.ftr=path/to/custom-footer.xml \
     --output=data-store/data/my-doc-set

Header templates support special interactive roles:

  • <document-title/> — Inserts the title of the document set.
  • role="search" — Renders the header search bar.
  • role="theme-toggle" — Renders the Light/Dark mode selector.
  • role="clear-chat" — Renders a clear chat conversation button in the AI Assistant.

Central Design System (chrome.json)

The chrome.json file (located at data-store/data/chrome.json) provides fallback header, footer, card, and chat interface templates. If a published document set does not include a custom header, the system automatically uses chrome.json to maintain consistent branding across all document sets.

Automated CI Publishing to GitHub Pages

You can automate documentation publishing using GitHub Actions. Add a workflow file at .github/workflows/docs-gh-pages.yml:

name: Build and Deploy Documentation to GitHub Pages

on:
  push:
    branches:
      - main
      - master
    paths:
      - 'react-harness/sample/**'
      - '.github/workflows/docs-gh-pages.yml'
  workflow_dispatch:

permissions:
  contents: write

jobs:
  build-and-deploy-docs:
    name: Build & Deploy DITA Documentation
    runs-on: ubuntu-latest
    steps:
      - name: Git Checkout
        uses: actions/checkout@v4

      - name: Build DITA AST Documentation
        uses: dita-ot/dita-ot-action@master
        with:
          install: |
            dita install fox.jason.extend.css
            dita install org.dita-bootstrap.html
            dita install org.dita-bootstrap.ast
          input: react-harness/sample/document.ditamap
          transtype: ast-bootstrap
          output-path: out/sample

      - name: Deploy Documentation to GitHub Pages
        uses: JamesIves/github-pages-deploy-action@v4.6.0
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
          branch: gh-pages
          folder: out/sample
